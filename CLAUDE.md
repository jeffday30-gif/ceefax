# Ceefax Reborn — Project Guide

A mobile-first PWA recreation of BBC Ceefax (1974–2012). Vanilla JS frontend
rendering a 40×25 character grid to canvas at the native SAA5050 12×20 cell
size. Node + Express backend with an in-memory cache fed by cron-scheduled
scrapers pulling from BBC News RSS, Open-Meteo, TVmaze and football-data.org.

## Live URLs

- **Production**: https://ceefax.onrender.com
- **Healthz** (cache status per data source): https://ceefax.onrender.com/healthz
- **GitHub**: https://github.com/jeffday30-gif/ceefax (push to `main` auto-deploys)
- **Render dashboard**: https://dashboard.render.com (service: `ceefax`, free plan)

## Architecture at a glance

```
public/             frontend - one HTML, one CSS, one JS, canvas renderer
  app.js              fetches /api/page/N, draws to canvas, handles keypad/swipe/sub-page cycle
  styles.css          Bedstead @font-face, keypad styling
  sw.js               service worker - bump VERSION on frontend changes to bust cache
  manifest.webmanifest  PWA metadata
  fonts/bedstead.otf  self-hosted public-domain Bedstead font
  icons/              generated by scripts/generate-icons.js
server/
  index.js            Express bootstrap, mounts routes, starts scrapers
  cache.js            in-memory Map: { key -> { payload, fetchedAt } }
  data.js             accessor layer - merges cached fields over stub fields
  routes/pages.js     GET /api/page/:number?sub=N
  routes/health.js    GET /healthz
  renderers/          one file per content domain; all share grid.js
    grid.js             Grid class - authentic header, section title bar, fastext, toJSON
    palette.js          8 SAA5050 colours + page-band → section colour map
    indexRenderer.js    pages 100, 152, 199
    newsRenderer.js     101-119, 150, 160, 170
    businessRenderer.js 200, 201, 220, 230
    footballRenderer.js 300-304, 306, 312, 316, 320, 324, 325
    worldCupRenderer.js 305, 306, 307, 326-329
    sportRenderer.js    340, 341, 360, 370, 374, 380, 390
    weatherRenderer.js  400-406, 410
    travelRenderer.js   430, 450
    entertainmentRenderer.js 500, 501, 510, 520, 540, 555, 570
    tvRenderer.js       600-605, 660, 680
    subtitlesRenderer.js 888
    index.js            top-level dispatch by page-number range
  scrapers/           one file per data source
    index.js            registers cron jobs, primes all on startup
    news.js             BBC News RSS (UK/World/Business) - every 15 min
    sportRss.js         BBC Sport RSS (10 sub-feeds incl. world-cup) - every 20 min
    weather.js          Open-Meteo - every 30 min
    tv.js               TVmaze - every 2 hours
    football.js         football-data.org - every 15 min (PL/ELC/WC standings, top scorers)
    bbcLive.js          BBC Sport HTML scrape (WC/PL/Championship) - every 5 min
    lottery.js          national-lottery.co.uk scrape - every hour (currently failing)
  stubs/              minimal skeleton fallbacks ONLY - no fabricated match data
scripts/generate-icons.js  pure-JS PNG encoder (no native deps) for PWA icons
```

## Page numbering

Late-1990s authentic + World Cup additions. 56 spec pages + 6 WC pages + page 152.

- **100** index, **152** Pages from Ceefax, **199** A-Z
- **101–119, 150, 160, 170** news
- **200, 201, 220, 230** business
- **300–304, 306, 312, 316, 320, 324, 325** football
- **305, 306, 307, 326–329** World Cup (305 = index, 326 = group tables sub-paged A–L)
- **340, 341, 360, 370, 374, 380, 390** other sport
- **400–406, 410** weather
- **430, 450** travel
- **500, 501, 510, 520, 540, 555, 570** entertainment
- **600–605, 660, 680** TV
- **888** subtitles homage

Section colours (header section bar): 100s red, 200s yellow, 300s green, 400s
blue, 500s/200s cyan, 600s magenta, 888/199 white. The top row (row 0) is
always black bg with coloured text elements (yellow page, white "CEEFAX",
cyan date, yellow clock with `/` between minutes and seconds).

## Run locally

```
cd C:\ceefax
npm install            # only first time
npm start              # loads .env automatically (FOOTBALL_API_KEY)
```

Then open http://localhost:10000 or http://<laptop-ip>:10000 from iPhone on same Wi-Fi.

## Deploy

`git push origin main` → Render auto-detects and rebuilds via `render.yaml` +
`Dockerfile`. First build is ~3-5 min (Docker cache empty), subsequent builds
~90 seconds. Health check at `/healthz` must return 200 before Render marks
the service Live.

## Secrets

- **FOOTBALL_API_KEY**: locally in `.env` (gitignored), remotely set in the
  Render dashboard under Environment. **Never commit it.**
- The `.env` file uses Node 22+ `--env-file-if-exists=.env` flag in the npm
  scripts; no dotenv package needed.

## Deviations from "obvious" assumptions (don't relitigate these)

1. **No SQLite** — `server/cache.js` is an in-memory Map. Render free has no
   persistent disk, so SQLite would just be in-memory with extra steps.
2. **News source = BBC RSS, not NewsAPI.org** — NewsAPI's free tier is
   localhost-only by ToS, blocks CORS off-localhost.
3. **Bedstead font is OTF, not WOFF2** — bjh21.me.uk only publishes OTF; iOS
   Safari accepts it via @font-face.
4. **Hosting = Render free**, instance sleeps after 15 min idle, ~30s cold
   start, no persistent disk. Scrapers re-prime on cold start (<3s).
5. **5th fastext colour is CYAN, not blue** — authentic SAA5050 convention.
6. **Sub-page cycle = 10s** — authentic Ceefax cadence, not 8s.
7. **Header row 0 is black bg with coloured text** — not a full coloured
   band. The coloured band lives on row 2 as a section title (`writeSectionTitle`).
8. **Fastext is contextual per page** — `g.setFastext([{label, page}, …])`
   inside each renderer, not a fixed global mapping.
9. **Entertainment kept at 500s** even though authentic post-1996 had Travel
   in 500s. User explicitly chose this layout.
10. **No fabricated data anywhere.** Stubs are skeleton-only (structural
    metadata like tournament name, host countries). Pages with no live feed
    show `DATA UNAVAILABLE` via `renderers/helpers.js`, NEVER invented match
    results, scores, or news. The user surfaced fabricated "England beat
    Senegal in Dallas" data on 2026-06-14 - never let this regress.
11. **Click-through**: cells can carry `l: url`. Client renders cyan underline
    and opens the link in a new tab on tap. Use this for BBC article links
    on news/sport headlines.

## Standing instructions for Claude (long-running collaboration)

- **Push to `main` is pre-authorized** for normal feature/bug/content edits.
  Don't ask for confirmation on every push — just push and report the URL.
- **Always bump `VERSION` in `public/sw.js`** when changing `app.js` or
  `styles.css`, otherwise users see the stale cached version.
- **Don't commit `.env`** — it's gitignored; verify before any commit.
- **Don't commit `.claude/`** — local-machine Claude settings, gitignored.
- **Confirm before** destructive git ops: `reset --hard`, force-push, branch
  deletion, history rewrites.
- **Confirm before** changing the data architecture (Map vs SQLite, scrapers
  → workers, etc.) or the hosting provider.
- **When adding a new page**: pick an unused number consistent with the
  numbering scheme above, add the renderer (or extend an existing one), add
  the dispatcher entry in `server/renderers/index.js`, update the A-Z list
  in `indexRenderer.js`, and add a contextual fastext.
- **When adding a new data source**: write the scraper in `server/scrapers/`,
  add it to `scrapers/index.js`, add the accessor to `server/data.js`, write
  a matching stub in `server/stubs/` so the renderer keeps working on cold
  start before the first scrape completes.
- **Visual changes need iPhone verification** — say so explicitly when a
  change might look wrong on mobile, since I can't see the canvas output.
- **Smoke test recipe**: `npm start`, then curl every page in the list above
  and check `/healthz` shows all relevant sources `"live"`.
